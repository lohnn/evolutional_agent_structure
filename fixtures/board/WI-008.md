## Spec / notes

THE FIXTURE THAT DID NOT EXIST, and whose absence is the point (WI-064).

Every fixture before this one was an item nobody had ever revised, so the
renderer's treatment of a revision entry was unrepresented rather than
considered — and `lineageSessions()` mislabelled spec editors as failed
attempts for as long as that stayed true.

It deliberately carries BOTH kinds of session-bearing entry at once, because
either alone proves nothing:

  - `ses_fixture_attempt_owner01` is a GENUINE prior attempt (start + demote).
    It MUST render as "previously attempted in".
  - `ses_fixture_editor_000001` only ever REVISED THE SPEC (status self-loop,
    `superseded` present). It must NOT — a reader of the item is not a failed
    worker (SCHEMA §4d).

The last entry is the DANGLING-POINTER shape: `superseded: e3b0c44298fc` is the
sha256 of the empty string, stamped by the pre-fix respec path onto an item
with no prior body. Nothing is archived behind it and `readRevision` returns
null. It is still a revision that genuinely happened, so it must still be
counted and shown — `transitions[]` is append-only (I-049) and history is not
tidied to make rendering easier.

`board/WI-008/6112ab181958.md` holds the one payload that DOES resolve, so
enumeration can be asserted to ignore the directory (SCHEMA §1).
